# I2C GPIO-expander Xschem benchmark

This benchmark uses the generated `i2c_gpio_2bit_fullchip.sym`. The user does not wire internal compiler nets.

## Generate it

First compile:

```bash
bio2rtl build examples/i2c_gpio_2bit/i2c-gpio-hw.dis
```

Then generate the benchmark:

```bash
bio2rtl benchmark examples/i2c_gpio_2bit/i2c-gpio-hw.dis
```

Output:

```text
build/xschem/i2c_gpio_2bit_i2c_benchmark.sch
build/i2c_electrical_benchmark_expected.json
```

## Parts placed in the benchmark schematic

1. **DUT**: `i2c_gpio_2bit_fullchip.sym`
2. **VDD source**: 3.3 V DC voltage source
3. **SCL source**: voltage source whose value is a generated PWL sequence
4. **SDA pull-up**: 4.7 kΩ from VDD to SDA
5. **Master SDA NMOS**: TR-1um NMOS used as an open-drain pull-down
6. **SDA master-gate source**: voltage source whose value is a generated PWL sequence
7. **GPIO0 input fixture**: 1 kΩ from VDD to GPIO0
8. **GPIO1 input fixture**: 1 kΩ from GPIO1 to VSS
9. **Ground**: VSS tied to SPICE node 0
10. **Simulation directive**: `.tran 0.05u <generated-stop-time>u` and saved SCL/SDA/GPIO traces

## Exact terminal connections

### DUT

- DUT `VDD` → 3.3 V net `VDD`
- DUT `VSS` → net `VSS` → SPICE ground
- DUT `SCL` → net `SCL`
- DUT `SDA` → net `SDA`
- DUT `GPIO0` → net `GPIO0`
- DUT `GPIO1` → net `GPIO1`

### SCL source

- positive terminal → `SCL`
- negative terminal → `VSS`
- value → generated PWL sequence between 0 V and 3.3 V

The default generated benchmark runs at 100 kHz to make the first transistor-level check conservative. The Ver.1 project target is 400 kHz; after 100 kHz passes, generate/modify the stimulus for 400 kHz and repeat the same checks.

### SDA pull-up

- resistor value: **4.7 kΩ**
- terminal 1 → `VDD`
- terminal 2 → `SDA`

### Master SDA open-drain NMOS

The benchmark never drives SDA high with a push-pull source.

- drain → `SDA`
- source → `VSS`
- body → `VSS`
- gate → `SDA_MASTER_LOW`

The gate is driven by a PWL voltage source:

- 0 V → NMOS off → SDA released → 4.7 kΩ pulls SDA high
- 3.3 V → NMOS on → SDA pulled low

The generated fixture currently uses a TR-1um `MN` with `w=30u`, `l=1u`, `m=9` for the master-side test pull-down. This transistor is a testbench device, not part of the generated DUT.

### GPIO input fixtures

GPIO0:

- 1 kΩ from `VDD` to `GPIO0`
- when DUT GPIO0 is high-Z/input, observed input = HIGH

GPIO1:

- 1 kΩ from `GPIO1` to `VSS`
- when DUT GPIO1 is high-Z/input, observed input = LOW

## Why PWL is used

A simple `PULSE()` source is sufficient for a free-running clock but not for the complete bus transaction, because the benchmark needs START, STOP, ACK slots, repeated START, byte writes, byte reads, master ACK/NACK, and idle pauses.

The generator therefore creates two PWL sources:

- `VSCL`: actual SCL waveform
- `VSDA_MASTER_LOW`: gate control of the master's SDA open-drain NMOS

The SDA bus voltage itself is **not** prescribed by a voltage-source PWL. It is the electrical result of the pull-up, master NMOS, and slave DUT. This is important because ACK and read data must be generated by the DUT.

## Directed transactions

The frozen I2C project uses 7-bit address `0x42`:

- write address byte = `0x84`
- read address byte = `0x85`
- mismatch test byte = `0x86`

The generated PWL sequence performs:

### 1. Direction register 0 → outputs

```text
START → 0x84 → ACK → 0x00 → ACK → 0x00 → ACK → STOP
```

### 2. Data register 1 → GPIO0=1, GPIO1=0

```text
START → 0x84 → ACK → 0x01 → ACK → 0x01 → ACK → STOP
```

Expected after the transaction:

- `V(GPIO0)` = HIGH
- `V(GPIO1)` = LOW

### 3. Direction register 0 → inputs

```text
START → 0x84 → ACK → 0x00 → ACK → 0x03 → ACK → STOP
```

Now both GPIO pins are high-Z/input. The external 1 kΩ fixtures impose GPIO0=HIGH and GPIO1=LOW.

### 4. Read register 2

```text
START
→ 0x84 → ACK
→ 0x02 → ACK
→ repeated START
→ 0x85 → ACK
→ read 0x01
→ master ACK
→ read 0xFF
→ master NACK
→ STOP
```

Expected read values:

- first byte = `0x01`
- second byte = `0xFF`

### 5. Address mismatch

```text
START → 0x86 → NACK → STOP
```

## What to plot

At minimum:

```text
V(SCL)
V(SDA)
V(GPIO0)
V(GPIO1)
```

Optionally also plot `V(SDA_MASTER_LOW)` to compare the master's requested low periods with the actual SDA bus.

## What a correct waveform must show

1. START occurs as SDA falls while SCL is high.
2. STOP occurs as SDA rises while SCL is high.
3. During normal data bits, SDA is stable while SCL is high.
4. For each valid write byte, the slave pulls SDA low in the ninth-clock ACK slot.
5. After DATA=`0x01`, GPIO0 is high and GPIO1 is low.
6. In input mode, GPIO0 follows its pull-up and GPIO1 follows its pull-down.
7. Read byte 1 is `00000001` (`0x01`).
8. Read byte 2 is `11111111` (`0xFF`).
9. Address `0x86` is not acknowledged.

## Run Xschem/ngspice

```bash
export PDK_ROOT="$HOME/pdk"
export PDK="TR-1um"
export BIO2RTL_XSCHEM_DIR="$PWD/build/xschem"

xschem --rcfile build/xschem/xschemrc.bio2rtl \
  build/xschem/i2c_gpio_2bit_i2c_benchmark.sch
```

Then netlist/run ngspice from Xschem and inspect the saved traces.

The Ver.1 freeze proved the directed digital transaction fixture and exact generated connectivity. The public package does not claim that a TR-1um transistor transient has already been run on the user's local PDK installation.
